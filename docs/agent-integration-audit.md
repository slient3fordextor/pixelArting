# AI 工作流接入审计

审计日期：2026-11-11。

## 结论

产品应优先交付一个独立的、版本化的 MCP 服务，把 PixelArting 的项目、素材、生成任务、质检、修复和导出能力暴露给客户自己的 AI 客户端。Godot、Unity、RPG Maker 等插件复用同一套 HTTP/JSON 合同，负责宿主内的资源选择、导入和结果展示；插件不复制素材规则和 AI 编排。

这样可以让客户从 ChatGPT、Codex、Claude、内部 agent 或自建工作流接入同一个服务，也避免为每个 AI 宿主维护一套不同的插件协议。需要 UI 时再增加 MCP Apps 资源；工具本身应先在没有 UI 的情况下完成完整工作流。

## 初次审计基线（实施前）

以下表格记录本轮实施前的状态；后续已交付能力见文末进展，未解决的生产接入要求仍有效。

| 能力 | 当前状态 | 结论 |
| --- | --- | --- |
| MCP stdio | `backend/mcp_server.py` 可启动，仓库提供 `.mcp.json` | 适合开发者本地使用，依赖工作区和 `.venv`，不是可分发安装包 |
| Streamable HTTP | 已支持 `/mcp`，默认绑定 loopback | 适合本机实验；没有认证、租户隔离和公网部署边界 |
| 读工具 | 项目、素材、版本、缩略图、配置、报告、质检 | 基础完整，但缺少标准 `search`/`fetch`，不适合作为知识或研究型连接器 |
| 写工具 | 新建、保存、改名、质检修复、恢复 | 有环境变量总开关和版本冲突保护；没有按用户/项目授权、幂等键、审批上下文和审计日志 |
| AI 生成 | 只有桌面 HTTP API，MCP 没有生成/轮询/取消/候选工具 | 外部 agent 不能调用核心 AI 工作流 |
| 导入/导出 | 桌面 HTTP API 有 PNG、JSON ZIP、Godot 等能力 | MCP 没有文件导入、导出、下载引用和批量操作工具 |
| 任务进度 | HTTP API 有持久化队列，MCP 未暴露任务资源或进度事件 | 长任务无法被外部 agent 稳定编排 |
| 结果形态 | FastMCP 函数直接返回 dict 或错误 dict | 缺少稳定 `structuredContent`、输出 schema、错误分类和可重试语义 |
| UI | 没有 MCP Apps resource/widget | 客户可以使用纯工具；候选对比等交互无法嵌入支持 MCP Apps 的宿主 |
| 发布 | 仅仓库脚本和相对路径配置 | 缺少独立版本、容器/包、健康检查、Inspector 回归和升级兼容策略 |

## 需要先解决的阻塞问题

1. **授权边界**：`PIXELART_MCP_ALLOW_WRITE=1` 只能作为本地开发保险丝，不能作为客户授权系统。远程服务必须在每次工具调用中验证身份、租户、项目权限和写入范围；高影响写入要保留宿主确认语义。API Key 不能进入 MCP 结果、日志或工具元数据。
2. **稳定合同**：工具名、输入、输出和错误要独立于 SQLite 和桌面 UI。每个工具需要显式 schema、版本策略、幂等语义、分页/限制和稳定 ID。
3. **异步工作流**：生成、导入、质检和导出都可能是长任务。需要 `start/get/cancel/retry` 任务合同、状态版本、进度和可恢复结果，而不是让模型等待一次同步调用。
4. **外部素材边界**：客户 agent 至少需要搜索项目/素材、读取预览、提交生成、查看候选、导入候选、运行质检、预览修复、提交修复和导出结果。当前 MCP 只覆盖其中的资产编辑子集。
5. **部署与运营**：需要独立服务入口、HTTPS、认证发现、限流、超时、结构化审计日志、指标、数据驻留策略和回滚兼容。loopback 服务不能直接当作客户远程服务。

## 推荐目标架构

```text
客户 AI 宿主 / ChatGPT / Codex / 自建 Agent
                       |
                 版本化 MCP Gateway
                 /                 \
       MCP tools + optional UI       OAuth / mTLS / tenant policy
                       |
             Workspace / Asset API
              |       |       |
          SQLite   AI queue  quality/export
                       |
                 Provider adapters

Godot / Unity / RPG Maker 插件 ---- 同一版本化 HTTP/JSON 合同
```

MCP Gateway 可以先和现有 FastAPI 进程同仓实现，生产部署时再拆成独立进程。桌面客户端和插件都走 Workspace API；MCP 不直接操作数据库，也不暴露 provider API Key。

## 按阶段重排

### P0：独立接入基础

- 明确 `v1` 资源、版本、任务、错误和权限合同，生成 OpenAPI 与 MCP schema。
- 将 MCP 数据根、认证上下文和 workspace 注入请求生命周期，移除全局单例 Store 对远程多用户形态的依赖。
- 实现本地 token/远程 OAuth 2.1 或 OpenAI-managed mTLS 的认证适配，所有工具执行项目级授权。
- 为写工具增加幂等键、确认要求、审计事件和不可逆操作保护；保留 `expectedCurrentVersionId` 冲突保护。
- 建立独立 MCP 包/容器/CLI，提供版本化配置、健康检查、迁移和一键本地启动。

### P1：AI 工作流 MCP

- 暴露 `search`/`fetch` 只读工具，以及项目、素材、预览、版本和质检读取工具。
- 暴露生成任务的 `start_generation`、`get_generation`、`cancel_generation`、`retry_generation` 和候选状态/导入工具。
- 暴露质检修复的 preview/commit 两阶段工具、导出任务和下载引用。
- 为长任务提供结构化状态、进度、事件和恢复语义；重复调用不产生重复任务或重复导入。
- 为需要视觉交互的候选审阅增加 MCP Apps widget；工具无 UI 时仍能完成整个工作流。

### P1：可运营与可验证

- 用 MCP Inspector 验证初始化、工具 schema、注解、错误、权限和重复调用。
- 建立跨宿主契约测试：只读 agent、写入 agent、冲突、取消、超时、重试、越权和敏感信息泄漏。
- 增加调用延迟、失败率、队列深度、provider 费用和审计事件指标，日志默认脱敏。

### P2：宿主插件

- 先做 Godot 插件：选择项目/素材、拉取导出包、导入 SpriteFrames/JSON、显示质检报告和触发同步。
- 再按客户需求增加 Unity、RPG Maker 等插件；插件只做宿主资源映射，不实现 MCP 工具和质量规则。

## 验收标准

- 一个没有打开桌面 UI 的客户 agent，可以通过独立 MCP 服务完成“查找素材 → 生成 → 查看候选 → 导入 → 质检 → 修复预览 → 提交 → 导出”。
- 同一工具在 stdio 和 Streamable HTTP 下返回相同的 schema、错误分类和版本语义。
- 未授权请求无法读取其他 workspace，也无法通过模型参数绕过项目权限。
- 重复请求、网络重试和并发调用不会重复创建版本、任务或导入素材。
- MCP Inspector、后端契约测试和至少一个真实宿主插件都能验证这一条端到端链路。

初审时 `docs/mcp.md` 描述本地单用户适配器。后续已增加独立包和单工作区 OAuth 适配器；客户生产接入仍需按下列实施进展和 TODO 验收。

## 第二阶段实施进展：本地 AI 工作流（0.3.0）

- 桌面 HTTP 与 MCP 共用持久化 GenerationService，移除 API 内专用执行器；同一工作区通过 OS 锁选择单一执行者，其他本机进程仍可提交、取消和读取，执行者退出后可接管。
- 新增生成 start/get/list/cancel/retry、候选预览/收藏/淘汰/导入工具，以及任务和 PNG 资源。状态返回 revision 和候选摘要，不暴露 provider 配置、密钥、外部 URL 或像素文档。
- 提交和重试使用持久化工作区幂等键，并发同键同请求复用任务；输入/操作不一致或原任务已删除时明确冲突。重试复用原 provider 快照。候选导入复用既有任务/候选/项目幂等语义。
- 修复等待档案锁的任务取消时可能释放其他任务锁的问题。HTTP 执行器绑定应用生命周期，避免无状态 MCP 请求结束时停止长任务。
- 真实 stdio/HTTP 客户端配合本机模拟 provider 跑通生成、候选预览、导入、质检、修复和导出；无外部付费调用。独立 wheel 在仓库外同样验证该链路，详见[实现状态](implementation-status.md)。

本地核心链路已有可执行验证，完整 P0 仍未完成：远程认证/项目授权、写确认与审计、限流、全部工具的合同和幂等、文件导入、任务推送事件、容器与升级/回滚回归、Inspector/客户宿主验收及可选 MCP Apps UI 仍需推进。进程崩溃后的恢复是至少执行一次，provider 可能重复收费，尚无外部请求恰好执行一次的保证。

## 第三阶段实施进展：HTTP 安全边界（0.4.0）

- 新增外部 OAuth 2.1 授权服务器的 JWT 资源服务器适配器：固定 issuer 与公钥，校验 access-token 类型、签名算法/kid、aud、workspace_id、主体、有效期，并发布受保护资源 metadata。没有自建授权/刷新/token 签发端点。
- token scopes 与服务端主体 grant 取交集；read、write、generate、admin 分开控制。所有 MCP 工具和资源共用集中授权边界，新工具默认拒绝。项目/任务列表按授权范围过滤，候选导入校验来源和目标，素材/任务/导出 URI 不能绕过项目限制。
- HTTP 缺失/无效身份返回 401，scope 或项目不足返回 403，预算超限返回 429；scope challenge 包含资源 metadata 和所需 scopes。进程只读门禁仍可拒绝任何 token 的写入。
- 新增工作区共享的固定分钟读写预算与不记录参数的审计。操作前落 attempt，操作后记 completed/failed，拒绝/限流单独记录；审计不可用时拒绝开始。日志记录 issuer/workspace/subject/client 身份，不记录 token、prompt、像素或 provider 原始响应。
- 系统钥匙串改为工作区 UUID 命名空间，避免不同数据库共用默认 provider 密钥。旧全局默认条目无法确认归属，升级后需要工作区所有者重新保存；UUID 档案/任务快照凭据仅按明确记录迁移一次。
- 通过隔离签名 token 验证伪造/跨受众/过期拒绝、并发主体隔离、跨项目工具和资源拒绝、共享预算，以及真实 SDK HTTP 授权修改/质检/导出。独立 wheel 从仓库外验证认证和项目隔离。

该阶段结束时，客户真实授权服务器浏览器授权与 TLS 代理验收、写入二次确认、无效 token/入口洪泛保护、认证失败审计、审计保留/归档、在线撤销和动态公钥轮换仍待完成。监听仍限制 loopback，远程入口需要管理员配置 HTTPS 反向代理。使用和边界见 [HTTP 安全接入](mcp-security.md)。

- 将全部 32 个工具及 10 项资源/模板的 scope、项目边界和写入属性集中声明，授权拦截与发现结果共用不可变登记表；未登记项拒绝，发现时校验读写注解一致性。
- 新增 `get_permissions`、`pixelart://contract/permissions/v1` 和发现元数据，区分当前有效 scope、进程写门禁、项目 grant 与配置的确认要求；客户端不能以元数据或查询结果代替服务端授权。
- 保留现有 scope/项目限制及每次写入确认。新增独立权限矩阵和真实 stdio/HTTP 断言，覆盖缺失 scope、跨项目、无项目任务、候选来源/目标、关闭写门禁及元数据篡改。使用和字段见 [权限合同](mcp-permissions.md)。

## 第十阶段实施进展：全部写工具的幂等合同（0.10.0）

- 为剩余 11 个写工具增加可选幂等键，旧客户端省略/null 兼容；全部 15 个写工具通过元数据和合同资源公开键要求、命名空间及重放类型。可靠自动重试需要保存原键与参数，见 [写入幂等](mcp-idempotency.md)。
- 通用写工具的业务修改、完整成功响应与结果引用同事务提交；嵌套 Store 调用复用所属线程/实例的连接。失败不占键，重放不覆盖后续编辑；原结果删除后保留收据并冲突。修复报告保存、输出验证和收据故障均纳入回滚。
- 取消在状态/收据提交后再通知本机执行器。所有重放仍经过当前身份、项目、写门禁、预算/审计与一次性确认，不承诺外部 provider 恰好执行一次。

## 第十一阶段实施进展：Workspace HTTP/OpenAPI（0.11.0）

- 独立 Streamable HTTP 进程新增 `/api/v1`，将现有 32 项工具映射为 HTTP 操作，另提供资源与合同读取。OpenAPI 3.1.1 从实际工具 schema、授权和幂等元数据构建，CLI、HTTP 与 MCP 合同资源共用输出；工具路由遗漏会在构建合同时失败。
- HTTP 与 MCP 共用项目权限、写门禁、确认、限流、审计和持久化幂等收据。输入拒绝未知/重复参数、路径覆盖、重复 JSON 键、非有限数值（含指数溢出）和超过 4 MiB 的请求；失败使用脱敏状态码与结构化错误。
- HTTP/OpenAPI 定向回归 57 项通过，覆盖全部操作的 scope、跨协议重放、候选/文件/项目导入、修复与质检、资源读取、生成执行器生命周期及无数据库的离线发现。独立安装验证与详细边界见 [Workspace API v1](workspace-api-v1.md)。
- 版本化 HTTP 合同已经落地；任务事件、provider 崩溃重放策略、运营保护、MCP Apps widget、发布及真实客户宿主验收继续保留在 P0。

## 外部接入依据

当前官方插件路线把 MCP 作为 ChatGPT/Codex 的服务端能力协议，可只提供工具，也可附加 MCP Apps UI；远程服务需要稳定的 Streamable HTTP `/mcp` 入口。工具应返回可校验的结构化输出，认证和授权必须在每次工具调用中由服务端执行，工具注解不能替代授权。生产端还需要 HTTPS、日志指标、限流、版本兼容和 Inspector/端到端验证。参考 [OpenAI MCP server guide](https://developers.openai.com/api/docs/mcp)、[MCP server and UI quickstart](https://developers.openai.com/plugins/build/app-quickstart) 和 [Build an MCP server](https://developers.openai.com/plugins/build/mcp-server)。
