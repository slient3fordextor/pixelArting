# MVP 质检与修复规格草案

状态：目标规格，本地参考实现见 backend；实际覆盖与限制见 [实现状态](implementation-status.md)。范围依据 [MVP 规格](mvp-spec.md)，坐标和版本语义依据 [素材格式](asset-format.md)。

## 1. 执行与结果约定

MVP 精确包含以下 8 个规则 ID 和 5 个修复 ID。检测按指定素材版本及配置快照运行，读取输入但不能修改输入；实现必须固定规则版本和参数。

每条启用规则的执行状态为 `passed`、`findings`、`skipped` 或 `failed`。禁用规则记为 `disabled` 且不调用检查实现。跳过记录原因，例如缺少调色板、基线标记或不适用的素材类型；失败记录错误，不伪装成零问题。

严重等级：`info` 为信息，`warning` 为建议，`error` 为配置不符，`blocking` 为无法继续对应操作。用户可以调节质检等级，但不能绕过解码、资源引用和导出包结构的操作前置验证。

所有规则默认启用；缺输入时跳过，不隐式开启其他规则。项目、临时检查参数先合并为完整快照，再执行；临时参数优先，未指定项继承项目配置。参数未知、类型错误或相互冲突应在执行前拒绝。

## 2. 八条规则

| ID | 判定与输入 | 建议等级 | 可选修复 |
|---|---|---|---|
| `size.grid` | 每帧实际宽高是否等于目标画布；Sprite Sheet 切分是否满足用户声明的单元格、边距和间距 | error | 最近邻缩放、透明画布补齐 |
| `palette.limit` | 全部帧的可见 RGB 去重数是否超过 `maxColors`；alpha 为 0 的 RGB 不计数 | error | 调色板映射 |
| `palette.membership` | alpha 大于 0 的像素 RGB 是否属于项目调色板；无调色板时跳过 | error | 调色板映射 |
| `transparency.halo` | 项目声明禁止半透明时，检查是否存在 `0 < alpha < 255`；允许半透明时跳过 | warning | 按阈值二值化 alpha |
| `animation.structure` | 动作/方向集合、预期帧数、帧引用、统一画布、正整数时长及 loop 元数据是否符合配置 | error | 仅尺寸子问题可补齐画布；缺帧或错误映射需人工处理 |
| `animation.baseline` | 同一动作中用户确认的每帧基线 `baselineY` 与目标基线偏差是否超过阈值；缺标记时跳过整组并列出缺失帧 | warning | 帧对齐 |
| `anchor.bounds` | 原点、基线和矩形碰撞数据若存在，是否为整数且在该帧允许范围内 | error | MVP 无自动修复，用户修改元数据 |
| `export.integrity` | 对选定导出目标，检查必需元数据、帧引用、文件路径映射和适配器声明的可表达能力；无导出目标时跳过 | blocking | MVP 无自动修复 |

首期画布已确认：`targetWidth=64`、`targetHeight=64`、`godotVersion=4.7.2`。其他默认参数：`maxColors=32`、`allowSemiTransparent=false`、`baselineTolerancePx=0`。目标基线、动作帧数和时长来自显式配置，不推测。

多图层默认检查可见图层合成结果。几何修复必须同步所有层，颜色/透明修复保留各层并以重检结果为准；不能为通过规则直接压平图层。隐藏层保留原像素，当前锁定层存在时修复计划被拒绝。图层 opacity 产生的半透明与混色需要单独调整，源像素二值化不保证合成结果成为二值 alpha。

### 2.1 不应误判的边界

- 栅格图像天然使用整数坐标；仅凭 PNG 不能证明它原来是否被非整数缩放。`size.grid` 只验证尺寸和已声明布局，不识别视觉风格。
- `transparency.halo` 这个 ID 检查的是禁止半透明的约束，不能证明白边或灰边一定是光晕。全不透明白色轮廓不会因此被删除；合法半透明特效应使用允许半透明的配置。
- 颜色计数使用跨帧 RGB 集合，不把同色不同 alpha 计为不同 RGB；alpha 是否合规由独立规则判断。
- 锚点和碰撞框存在不代表语义合理；`anchor.bounds` 不生成碰撞框，也不判断碰撞范围是否符合角色身体。
- 动画 loop 标志可验证，但循环接缝是否自然、角色是否跨方向漂移和步态是否可读需要人工检查，MVP 不宣称自动判定。

尺寸和半透明检查不依赖调色板检查。规范化只做解码和结构转换；不能先量化、缩放或清除 alpha，再声称原素材通过质检。

## 3. 五个修复动作

| ID | 必需参数与前置条件 | 变更与损失风险 | 重检目标 |
|---|---|---|---|
| `resize-nearest-v1` | 目标宽高为正整数；用户确认缩放比例 | 最近邻重采样；非等比缩放可能变形、缩小可能丢细节；坐标元数据需同步变换 | 尺寸符合目标，坐标仍有效 |
| `map-palette-v1` | 非空且不超过 `maxColors` 的目标调色板 | 对可见 RGB 做确定性映射，保留 alpha；可能合并细节和改变配色 | 颜色数量和调色板成员检查通过 |
| `remove-halo-v1` | 显式选定二值透明策略及 `alphaThreshold`，范围 1..255；建议初值 128 待验证 | alpha 小于阈值设为 0，其余设为 255，透明 RGB 归零；会删除或加重边缘，不能还原真实背景色 | 不再有半透明像素 |
| `pad-canvas-v1` | 目标画布不小于原画布；提供整数偏移，全部内容可放入 | 添加透明画布并平移坐标元数据；不裁切、不缩放 | 帧尺寸统一，原有可见像素无损 |
| `align-frames-v1` | 每帧有人工确认的基线及目标基线；平移后可见像素与元数据不越界 | 整数纵向平移；画布不变，不能容纳时拒绝并提示先调整画布 | 基线偏差满足阈值且未裁切 |

调色板映射建议采用 RGB 三通道平方距离，等距时按调色板顺序选择，MVP 不加抖动。调色板顺序属于配置快照；若以后改变色彩空间或算法，必须升级修复版本。

缩放元数据采用各轴比例映射、非负坐标四舍五入（半值向上）；矩形左右/上下边界分别映射后计算宽高。映射后锚点越界或矩形退化为零面积时拒绝提交，要求人工调整。不静默钳制坐标。

平移修复同时更新原点、基线和碰撞框。检查源图中 alpha 大于 0 的所有像素是否能完整保留；修复器不能为了满足尺寸规则偷偷裁掉脚部或碰撞框。修复失败不代表规则可以自行禁用。

## 4. 修复计划与提交

计划包含 `baseVersionId`、`reportId`、Finding ID、有序动作列表、各动作版本和参数、完整配置快照、执行器版本以及预览结果的 checksum。

1. 验证报告与基础版本匹配，Finding 和规则允许的动作匹配，前置条件齐全。
2. 在副本上按显式顺序执行，不后台重排。例如画布补齐可先于基线对齐；颜色映射不会消除半透明。
3. 展示每帧差异、变化像素数、尺寸及元数据变化，允许选择或放弃；草稿修改后预览失效。
4. 用户确认后校验当前版本仍为基础版本，使用幂等键提交。相同键及参数返回相同结果；相同键不同参数报冲突。
5. 保存全部文件及元数据后原子发布新版本，再生成新报告。执行失败保留父版本，未提交文件不得暴露为正式版本。

`autoFix.enabled` 表示允许生成和选择修复计划，`allowed` 限制可用动作；MVP 仍要求确认预览。无人值守批量自动应用属于后续能力。

修复器是确定性的，但“重复应用一个修复”不保证无变化；提交幂等通过请求键实现。版本、参数和输入一致时应得到同样输出。无变化的计划标记为 no-op，不重复创建版本。

## 5. Finding 与报告示例

```json
{
  "id": "finding_1",
  "reportId": "report_1",
  "assetVersionId": "version_1",
  "ruleId": "transparency.halo",
  "ruleVersion": "1.0.0",
  "severity": "warning",
  "frameId": "frame_down_walk_0",
  "region": {"x": 12, "y": 8, "width": 6, "height": 4},
  "message": "当前配置禁止半透明，发现半透明像素",
  "canAutoFix": true,
  "fixIds": ["remove-halo-v1"]
}
```

`region` 是问题包围矩形，不表示矩形中的所有像素都应修改；精确修复需重新计算像素集合，或使用带校验值的掩码。多个合法区域应分别记录或提供区域列表，不能拿包围矩形直接擦除。

报告保存版本 ID、合并后的配置及 hash、规则实现版本、引擎/执行器版本、各规则执行状态和问题列表。失败或跳过的规则不能被汇总成“全部通过”。修复后新报告关联旧报告用于比对，旧报告与 Finding 保持不可变。

## 6. 样例验收

每条规则至少准备通过、违反约束和边界输入；每个修复准备可修复、拒绝执行和无变化样例。尚未建立样例集，以下是必须覆盖的场景：

- 32 色通过、33 色不通过；全透明像素的任意 RGB 不改变色数；目标调色板为空时不能映射。
- 不同 alpha 的同一 RGB 只计一种颜色；半透明合法配置跳过二值透明规则；阈值边界结果固定。
- 错误 Sprite Sheet 布局不猜测切分；缺方向/动作不自动复制帧冒充补齐；时长为零被报告。
- 基线未标记时跳过；目标相同为 no-op；对齐会裁掉像素时拒绝；合法 padding 保留所有可见像素。
- 原点等于帧宽或帧高时越界；碰撞矩形可贴画布边界但不能超出。
- 禁用规则不执行；缺条件、实现异常和不适用分别得到正确状态；报告配置变更后旧报告不变。
- 旧预览提交报冲突；重复确认只提交一次；中途失败不发布版本；导出引用不存在的帧时必须失败。
