# 素材栏右键与复制粘贴调研

调研日期：2026-10-12；实现更新：2026-10-28。状态：项目素材侧栏、确认收录素材库、跨项目搜索、复制到当前项目和应用内完整快照复制粘贴已实现；标签、回收站、系统剪贴板和独立预览仍是后续候选。当前实现与设计差异以 [桌面客户端](desktop-client.md) 和 [实现状态](implementation-status.md) 为准。

当前收录规则：新建、导入、粘贴和创建副本只进入左侧项目素材列表；用户对已保存素材点击“加入素材库”并确认后，才保存独立快照。素材库只负责复用这些确认过的快照，来源编辑或删除不影响它，移出素材库也不删除项目素材。下面的调研和候选菜单不代表所有项目素材都会自动进入素材库。

## 1. 官方资料与结论

| 参考产品 | 查到的行为 | 对本项目的启发 |
|---|---|---|
| Godot 4.7.2 | 文件对象菜单有打开、重命名、Duplicate、移动和删除；空白处由独立函数生成新建文件夹、场景、脚本、资源等菜单 | 右键对象和右键容器应独立定义，命令必须有明确目标 |
| Unity 6 | Project 窗口支持素材预览、缩略图大小、名称/类型/标签搜索；Duplicate、Rename 和 Delete 针对选中素材 | 管理素材还需要搜索、排序和视图切换，不能只增加删除按钮 |
| Aseprite | 时间轴区分图层、帧和 cel；图层、帧和 cel 可以通过剪贴板在文档之间复制粘贴 | 剪贴板要区分数据类型；完整素材复制应保留多图层和动画 |
| Krita | 资源管理支持名称/标签过滤、缩略图缩放；删除可停用资源，之后显示已删除资源并恢复 | 后续增加标签、多选和回收站有价值，但需真正提供恢复能力 |

资料来源：[Godot 4.7.2 文件系统面板源码](https://github.com/godotengine/godot/blob/4.7.2-stable/editor/docks/filesystem_dock.cpp)、[Unity 6 Project 窗口](https://docs.unity3d.com/6000.0/Documentation/Manual/ProjectView.html)、[Aseprite 时间轴](https://www.aseprite.org/docs/timeline/)、[Krita 资源管理](https://docs.krita.org/en/reference_manual/resource_management.html)。

需要区分事实与设计推导：Godot 的 `Copy Path`、`Copy Absolute Path`、`Copy UID` 复制的是标识，不能据此说其文件面板已有完整素材剪贴板。Unity 上述手册也不能作为其右键菜单包含素材复制粘贴的证据。Aseprite 的资料描述时间轴内容复制，并不是本项目这样的素材库。下面的菜单是结合这些资料和项目现状提出的设计。

## 2. 分开三个上下文

### 2.1 右键某个素材

| 分组 | 菜单项 | 行为与条件 |
|---|---|---|
| 查看 | 打开编辑 | 打开右键的素材；切换前处理当前未保存草稿 |
| 查看 | 预览 | 独立查看真实图像或动画，不改变当前编辑素材；预览窗口后续补充 |
| 管理 | 重命名 | 修改素材名称，保留像素、图层和动画；持久化需版本冲突检查 |
| 复制 | 复制素材 | 放入应用素材剪贴板，暂不新增素材 |
| 复制 | 创建副本 | 立即在当前项目新增独立素材，无需再粘贴 |
| 输出 | 导出 > 当前帧 PNG / 分层 JSON 包 / Godot 包 | 使用右键素材的数据；未打开的素材默认首帧，当前素材默认当前帧 |
| 查看 | 查看版本 | 打开目标素材的版本面板，切换前处理未保存草稿 |
| 危险操作 | 删除素材 | 放在底部并分隔，沿用名称、全部版本和不可撤销提示 |

菜单名称使用“复制素材”和“创建副本”，避免把现有的“复制图层”误认为整份素材复制。新建素材和导入素材放到素材栏空白菜单及已有工具按钮，不必占据每个素材对象菜单。

重命名应同步素材列表名称与 `Document.name`，不能只改一处。当前编辑素材的重命名纳入草稿并在保存时形成新版本；非当前素材基于指定版本创建改名版本并原子更新名称和当前版本，遇到冲突要求刷新。导出沿用现有保存版本约束：当前素材有草稿时先明确要求保存，不能悄悄导出旧像素。副本不受原素材图层锁定的阻止，但复制后保留锁定状态。

### 2.2 右键素材栏空白处

| 分组 | 菜单项 | 行为与条件 |
|---|---|---|
| 添加 | 新建素材 | 默认 64×64，一个透明图层；沿用尺寸输入 |
| 添加 | 导入 > PNG / Sprite Sheet | 使用现有导入能力 |
| 添加 | 粘贴素材 | 将素材剪贴板内容作为新素材加入当前项目；剪贴板为空或类型不符时禁用 |
| 列表 | 刷新素材列表 | 重新读取列表和版本化缩略图，不丢弃当前草稿 |
| 列表 | 排序 > 名称 / 最近更新 / 创建时间 | 不改变素材数据；最近更新时间需补充列表字段或查询 |
| 列表 | 视图 > 缩略图 / 详细列表 | 改变展示方式，保留真实预览；后续可增加缩略图尺寸 |

“粘贴素材”添加新条目，不把内容画到当前图层，也不覆盖已有素材。只有项目有效且操作可执行时才启用。尚未支持的系统图片、文件和文本粘贴不能显示为可执行的素材粘贴。

### 2.3 项目入口与文本输入

新建项目、切换项目放在项目标题或全局文件菜单；不让整个侧栏都弹出素材空白菜单。事件范围应分别为项目标题、素材条目、素材列表空白区，避免右键项目选择器或底部状态也被当成素材栏空白处。

名称输入、搜索输入等文本控件继续使用原生文本复制粘贴。键盘快捷键按焦点分派：素材栏使用素材剪贴板，文本框使用文本剪贴板。未来画布、图层和帧剪贴板另有类型，不通过全局事件把所有 `Ctrl/Cmd+C/V` 都解释为素材操作。立即创建副本可使用素材栏焦点下的 `Ctrl/Cmd+D`。

## 3. 复制什么，以及如何粘贴

### 3.1 第一阶段使用应用内剪贴板

桌面窗口使用一个应用内素材剪贴板接口，第一阶段保存当前窗口会话内的完整、不可变快照。复制成功后才替换剪贴板；读取失败保留原内容并报错。不向系统剪贴板写入大段 PNG/JSON，也不声称已经支持跨窗口、关闭重启后粘贴或其他软件之间交换。

复制当前正在编辑的素材时，快照取当前草稿，包括未保存内容；操作反馈明确“已复制素材（含未保存编辑）”，不自动保存、不清除未保存标记。复制其他素材时读取该条目指定的保存版本。数据准备期间如条目版本变更，应要求刷新后重试，避免复制与缩略图不一致的内容。复制的修复预览不属于草稿，必须先应用修复才能纳入快照。

快照至少包含：

- 完整 `Document`：所有帧的所有图层 PNG、图层顺序、显隐、锁定、不透明度。
- 动画的动作、方向、循环、帧引用和时长；每帧的原点、基线、碰撞矩形。
- 素材名称、类型及来源信息 `provenance`；已有来源或授权说明原样保留，未知的授权不补造。
- 剪贴板类型、格式版本、来源素材 ID、来源保存版本 ID，以及快照校验值；复制草稿时标记草稿来源，不把保存版本 ID 当成草稿的精确版本。

粘贴创建新的素材 ID 和初始版本，不继承原素材的历史、质检报告、修复预览、当前选中帧或撤销栈。帧和图层 ID 是文档内标识，可以保留，但所有引用必须仍然一致。数据库引用和可编辑内存对象应彼此独立；编辑副本不能影响来源素材。

剪贴板保存实际数据，不能只保存素材 ID；这样来源素材在复制后被编辑或删除，仍可粘贴原来的快照。不可变的原始文件可以按哈希共用，删除和清理不能破坏副本引用。

### 3.2 粘贴与创建副本

允许在同一窗口内切换项目后粘贴，目标归属当前项目。默认名称为“原名称 副本”，重名则使用“原名称 副本 2”等；遵守名称长度上限，从基础名称截断后再追加后缀，不覆盖同名素材。

后端按现有 `Document` 和 PNG 解码规则重新验证快照，包括 512×512、16 图层、64 帧、总像素限制及动画引用。新增素材和初始版本在同一事务完成，失败不留下空条目。即使剪贴板来自应用内部，也不能绕过校验。

当前有未保存草稿时，粘贴或创建副本只增加列表条目并保留当前编辑对象；没有草稿时可自动打开新素材。后续点击新素材仍走正常切换确认，避免因粘贴丢失正在绘制的内容。“创建副本”直接使用同样的快照和新增流程，不更换用户剪贴板内容。

素材复制保留隐藏图层和锁定属性，与当前“复制图层”后解除副本锁定的行为有区别；图层复制属于编辑工具，整份素材复制属于文档复制。PNG 导出依旧只合成可见图层。

### 3.3 后续系统剪贴板

后续可让桌面适配器提供系统图片/文件剪贴板，其他客户端适配器根据自身权限和能力提供受支持格式。图片粘贴到素材栏创建新素材，粘贴到图层区域导入新层；两者都不得隐式裁剪、缩放或替换现有像素。剪贴板失败要保留原草稿。

来源授权、跨应用格式和安全限制需单独定义，应用内素材剪贴板不会自动变成各引擎都能识别的协议。跨引擎输出仍走 [技术选型](technology-selection.md) 与 [素材格式](asset-format.md) 中的版本化接口和导出包。

## 4. 其他值得补充的内容及顺序

| 阶段 | 建议内容 | 理由或依赖 |
|---|---|---|
| 优先实现 | 两类菜单分开、素材复制/粘贴、立即创建副本、重命名、目标正确的导出和版本入口 | 对应当前反馈，形成完整单素材管理流程 |
| 随后补充 | 搜索、名称/时间排序、列表刷新、预览、视图切换和缩略图尺寸 | 素材增加后仍能定位和比较 |
| 随后补充 | 多选、批量导出/删除、标签、收藏、回收站与恢复 | 需明确选择集合、部分失败和恢复数据保存规则 |
| 后续扩展 | 文件夹、剪切/移动、系统剪贴板、跨窗口复制 | 需真实层级、原子移动和平台能力适配 |
| 按需求扩展 | 关联源文件、重新导入、引擎同步状态 | 需来源路径与变更冲突策略，不能覆盖当前编辑 |

当前素材保存在 SQLite 与哈希 PNG 文件中，没有每个素材对应的可编辑源文件。因此现在不加入“在文件管理器显示素材”或“复制素材路径”；如需定位，只提供语义明确的工作区目录入口。没有源文件关联时也不加入“重新导入”。

剪切不能在执行时先删除来源；真正的移动需要在目标写入成功后原子更新归属，并处理版本冲突。回收站也不能只换删除菜单名称，必须有软删除状态、恢复入口和清理策略；此前仍使用已实现的永久删除确认。

## 5. 交互与验收

右键仅记录目标素材 ID，不立即切换工作台或覆盖草稿。菜单动作读取该目标的内容和版本，不能默认使用当前打开素材。忙碌、版本冲突、无项目、空剪贴板等状态必须给出正确的禁用或错误反馈。

需要覆盖的验收场景：

1. 正在编辑 A 时右键 B，复制、改名、导出、删除均针对 B，A 的草稿不变。
2. 复制包含隐藏/锁定图层和多帧动画的素材，粘贴后所有像素、属性、引用和时长一致；随后修改副本不影响原件。
3. 复制当前草稿不保存原素材；粘贴后得到所见内容，不误用旧保存版本或未应用修复预览。
4. 复制后修改/删除来源仍能粘贴；跨项目粘贴创建新素材；连续粘贴正确处理重名和长度。
5. 空/错误类型剪贴板不能粘贴；请求失败不清空原剪贴板、不创建半成品；无效 PNG 或结构被后端拒绝。
6. 新增副本和粘贴不丢当前草稿；当前有草稿时导出不会静默使用旧版本；重命名同步列表与文档且保留历史。
7. 文本输入保留原生复制粘贴；菜单可用键盘操作、边缘不溢出，右键空白处和素材项显示不同内容。

核心范围已按本文完成并验证；后续候选不自动视为已排期。
