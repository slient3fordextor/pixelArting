# AI 像素素材平台产品文档

状态：产品规划，已开始本地原型实现。本文描述目标产品；首期范围以 [MVP 规格](mvp-spec.md) 为准，当前功能见 [实现状态](implementation-status.md)，规则和素材约定分别见 [质检规格](quality-rules.md) 与 [素材格式](asset-format.md)。

## 1. 产品概述

### 1.1 产品定位

面向独立游戏开发者、小型工作室和 RPG Maker/Godot 创作者的 AI 像素素材工作台。

产品覆盖从素材生成、像素级编辑、可配置质检、自动修复到游戏引擎导出的完整流程。

核心定位：

> 让 AI 生成的像素素材可以直接进入游戏项目，并且可验证、可修复、可重复生产。

### 1.2 解决的问题

通用图像生成工具可以快速生成视觉草图，但游戏素材通常还需要人工处理：

- 尺寸和像素网格不符合项目规范
- 颜色数量和调色板不统一
- 透明背景存在白边或半透明残留
- 同一角色在不同方向和动作中发生漂移
- 动画帧尺寸、锚点和循环不一致
- 生成结果缺少碰撞框、原点和引擎元数据
- 素材需要在多个工具之间反复转换

### 1.3 目标用户

| 用户 | 主要需求 | 付费理由 |
|---|---|---|
| 独立游戏开发者 | 快速获得可用角色、物品、Tileset 和动画 | 节省外包和手工处理时间 |
| Godot/RPG Maker 创作者 | 直接导入项目，减少格式转换 | 降低技术门槛 |
| 小型游戏工作室 | 保持项目内的风格和资源规范 | 降低返工和沟通成本 |
| 像素艺术初学者 | 生成草稿并自动修复常见问题 | 更快完成可用素材 |

### 1.4 产品边界

首期聚焦 2D 游戏素材，不覆盖完整游戏制作、3D 模型和长视频生成。

## 2. 核心功能

本节包含长期功能方向，不代表全部属于 MVP。首期只处理角色和单图，其他素材类型及高级编辑能力按 MVP 功能矩阵排期。

### 2.1 素材生成

- 文本生成角色、NPC、敌人、物品、建筑、背景、VFX 和 Tileset
- 上传草图或参考图生成变体
- 选择目标分辨率、视角、动作和颜色风格
- 保存项目级风格规范
- 基于同一角色生成四方向或八方向素材
- 生成 idle、walk、run、attack、hurt、death 等动作

### 2.2 像素编辑

- 铅笔、橡皮擦、填充、选区、移动和缩放
- 调色板管理和颜色替换
- 图层、帧和动画时间轴
- 透明背景编辑
- 撤销、重做和版本恢复

### 2.3 可开关的质检规则

质检规则彼此独立，可以单独启用、禁用或组合成检查配置。

目标规则类别（MVP 的 8 个具体规则见 [质检规格](quality-rules.md)）：

- 尺寸和像素网格
- 颜色数量和调色板一致性
- 抗锯齿和非整数像素
- 透明背景和边缘光晕
- 动画帧尺寸、数量、对齐和循环
- 角色锚点、原点和漂移
- 碰撞框和可交互区域
- Tileset 拼接和边缘连续性
- 图层命名和空图层
- 引擎导出格式完整性

每条规则输出：问题位置、严重等级、解释、修复建议和可选自动修复动作。

### 2.4 自动修复

- 最近邻缩放和网格对齐
- 颜色量化和调色板映射
- 去除白边、灰边和半透明残留
- 统一动画帧尺寸和角色基线
- 自动补齐透明画布
- 生成或调整碰撞框、原点和锚点
- 自动切分 Sprite Sheet
- 修复 Tileset 边缘和重复图案

所有自动修复都应支持预览、撤销和重新检测。

### 2.5 引擎导出

MVP 导出：

- PNG 单图、帧序列和 Sprite Sheet
- Godot SpriteFrames 资源包
- JSON 形式的帧、锚点、可选碰撞框和规则报告

后续导出：

- Aseprite 原生文件或兼容数据
- Godot TileSet 和编辑器插件
- RPG Maker 资源尺寸和命名规范
- Unity Sprite Atlas 与基础元数据

## 3. 典型工作流

### 3.1 生成新角色

1. 创建项目并设置分辨率、视角和调色板。
2. 输入角色描述或上传草图。
3. 生成多个候选结果。
4. 选择一个结果并生成方向和动作。
5. 运行用户选中的质检规则。
6. 预览并应用自动修复。
7. 导出到目标引擎。

### 3.2 修复已有素材

1. 上传 PNG、Sprite Sheet 或项目资源。
2. 选择快速、严格或引擎专用检查配置。
3. 查看按严重等级排序的问题。
4. 单项或批量应用修复。
5. 重新检查并导出修复后的版本。

## 4. 质检配置

目标内置配置（MVP 仅使用已定义规则，其他检查配置后续提供）：

- **快速检查**：尺寸、透明背景、抗锯齿
- **严格像素检查**：网格、颜色数量、调色板和边缘
- **动画检查**：帧数、基线、锚点、循环和漂移
- **Godot 检查**：SpriteFrames、TileSet、碰撞和目录结构
- **RPG Maker 检查**：尺寸、命名和资源目录规范
- **自定义检查**：用户自由开关规则并保存为项目配置

## 5. MVP 范围

阶段一完成上传处理闭环，阶段二补齐生成、最小编辑器和 Godot 导出；两个阶段都验收通过后才称为 MVP。完整范围、异常流程和待决项见 [MVP 规格](mvp-spec.md)。

### 必须包含

- Web 工作台
- PNG 图片上传与文本生成；生成能力先做样例验证
- 64×64 角色素材处理
- 多图层编辑、顺序、显示、锁定与不透明度；分层数据跨版本保留
- 四方向和基础 idle/walk 动画
- 8 个独立确定性质检规则，具体 ID 见质检规格
- 5 个确定性修复动作，具体 ID 见质检规格
- Godot 4.7.2 SpriteFrames、合成 PNG 和分层 JSON 包导出
- 版本、撤销和修复前预览

### 暂不包含

- 自训练基础模型
- 完整 3D 资产生成
- 多人实时协作
- 完整游戏关卡编辑器
- 面向大型工作室的权限和审批系统
- Tileset、其他引擎和原生 Aseprite 格式
- AI 语义漂移判断、局部重绘和收费系统

## 6. 商业模式

- 免费版：每月少量生成次数，基础质检和 PNG 导出
- 创作者版：私有素材、更多生成额度、动画和引擎导出
- 工作室版：批量处理、项目规范、团队权限和 API
- API/插件版：按调用量或项目数量收费

建议先验证订阅模式，再决定是否增加按量计费。

## 7. 关键指标

- 从提示词到可导入素材的平均耗时
- 自动修复后无需人工修改的比例
- 单个素材平均返工次数
- 质检规则的启用率和修复采纳率
- 导出后成功导入引擎的比例
- 首周留存和付费转化率
- 每个活跃用户每月生成和修复的素材数

## 8. 产品风险

- 生成模型输出质量不稳定
- 同角色跨动作和跨方向的一致性不足
- 用户对 AI 生成素材的商业授权存在疑问
- 图像生成成本可能高于订阅收入
- 规则过多会增加界面复杂度

应对策略是把确定性检查和修复优先做扎实，把 AI 判断限制在确实需要语义理解的场景，并为每个生成结果记录模型、提示词、参考图和授权信息。

## 9. 验证计划

1. 访谈 20 名 Godot、RPG Maker 或独立游戏开发者。
2. 收集他们最近制作角色动画和修复素材的实际耗时。
3. 做一个只支持角色四方向、动画和质检的原型。
4. 邀请 5 名用户用真实项目试用。
5. 以“导入引擎后无需返工”为核心指标验证付费意愿。
