# MCP v1 写入幂等

0.10.0 为其余 11 个写工具增加可选 `idempotency_key`。全部 15 个写工具现在均公开键参数和重放规则；兼容旧客户端的可选键省略或传 null 时沿用旧语义。需要在网络断开后安全重试的客户端必须提供键，并保存原调用参数。

## 发现与命名空间

能力 `features` 包含 `write-idempotency`。工具发现项 `_meta["pixelarting/idempotency"]` 描述参数名、是否必填、命名空间、重放类型和合同 URI；`pixelart://contract/idempotency/v1` 汇总规则，入口合同的 `idempotencyContractUri` 指向它。CLI `--schema` 输出相同元数据。

| 命名空间 | 工具 | 键要求 | 重放结果 |
| --- | --- | --- | --- |
| `mcp-writes` | 新建项目/空素材、配置更新、文档更新、改名、修复预览/提交、版本恢复、任务取消、候选状态/导入 | 可选，可靠重试时必传 | 原始成功响应快照 |
| `generation-requests` | start_generation、retry_generation | 必填，保留旧合同 | 原任务的当前状态 |
| `file-import-requests` | import_asset_file | 必填，保留旧合同 | 原始导入身份，按当前项目配置重算质检 |
| `project-import-requests` | import_project_backup | 必填，保留旧合同 | 原始恢复身份，按当前项目配置重算质检 |

键在单工作区的对应命名空间内唯一。`mcp-writes` 的 11 个工具共用命名空间，换工具也要换键；其他命名空间彼此独立，升级不改变原有键的含义。键是 1..128 个 ASCII 字母、数字、下划线、点、冒号或短横线，不含路径和空白。客户端可使用 UUID。

## 调用与重放

```json
{
  "name": "rename_asset",
  "arguments": {
    "asset_id": "asset-id",
    "expected_current_version_id": "version-before-edit",
    "name": "player-idle",
    "idempotency_key": "request-7f65"
  }
}
```

这是 MCP tools/call 参数示例，实际 ID 应来自 `get_asset(include_document=true)`。响应形状不变；旧对象直接位于 structuredContent，任务/候选联合类型仍位于 structuredContent.result，没有额外的 replayed 字段。

`mcp-writes` 以工具名与 SDK 解析后的参数计算规范化 JSON SHA-256，补齐函数参数缺省值并排除键本身；对象键顺序无关。嵌套 document/config 的显式字段仍参与摘要，不承诺将领域等价输入视为同一请求。同键换操作、名称、目标、版本、修复动作或其他参数，返回 `idempotency_conflict`。

首次成功时，业务修改、完整成功响应和所需结果引用在同一个 SQLite immediate 事务提交。失败，包括工具返回的业务失败、报告保存失败或收据落库失败，会回滚全部业务修改且不占用键。并发调用通过数据库写锁串行检查；重启和提交后丢失响应仍可读取同一收据。数据库忙/安全审计失败等不确定错误后应检查状态，再用原键和原参数重试。

重放返回首次成功的响应快照，不重新执行工具，也不撤销后来的编辑。例如改名成功后用户再次改名，原键重放仍返回第一次的版本和名称，但当前素材保持用户后来的版本。配置、候选状态和质检报告也按首次快照返回；后续编辑必须重新读取当前状态。修复提交的报告 ID 不因同键重试而重复创建。

收据检查原始项目、素材、结果版本、预览、报告或任务等所需引用。原结果被删除时保留收据并报冲突，不重建资源。权限或目标检查可能更早拒绝请求。候选的自然导入身份和修复 previewId 的旧重放规则仍保留；没有通用键时不增加新的自动重试保证。

## 权限与取消

重放前照常检查当前 OAuth scope、项目所有权、进程写门禁、限流、审计和已配置的一次性确认。键不是授权凭证；权限被撤销或实例改为只读后不能读取写收据。启用确认时，每次重放仍需审阅并批准新的确认请求，完整参数包括幂等键，见 [权限合同](mcp-permissions.md) 和 [安全接入](mcp-security.md)。

任务取消的持久化状态和收据一起提交，之后才唤醒本机执行器；收据失败不会提前发送内存取消信号。同键重放可再次唤醒执行器，但不重复改写状态。远程 provider 在取消到达前可能已经执行或收费。

## 持久化与边界

收据位于工作区业务数据库，保存响应快照、结果引用、工具和请求摘要，不保存完整输入参数；响应本身可能含素材文档，按工作区数据管理。安全审计仍不记录参数。收据无过期/自动清理策略，不能通过删除收据来重试不确定写入。工作区备份应包含整个数据目录；旧版本回滚应恢复升级前离线备份。

保证覆盖本地数据库事务。生成任务的入队去重、文件/项目导入沿用各自合同；远程 provider 执行和崩溃恢复不保证恰好一次或免于重复收费。OpenAPI、任务事件、运营清理策略与真实客户宿主验收仍见 [TODO](todo.md)。
